# ADR-001 : [OS Type 결정]

* **proposed**
* **@jjsair0412(주진성)**
* **2026-09-20** 
* **Issue URL : https://github.com/jjsair0412/Kubernetes-Architecture-Design-Record-Based-on-Measured-Data/issues/3**

## 맥락 및 문제 정의 (Context and Problem Statement)

* K8s 아키텍처 수립 전 OS Type 정의 필요

## 의사결정 요인 (Decision Drivers)

* OS 영역의 휴먼에러를 최소화할 수 있는 Immutable OS 지원
    >TCO 높을 경우 해당 요구사항 폐기. 비용 최소화가 1순위
* 장애 발생 시 빠른 재해복구 수립 절차 필요
* cgroup v2 공식 지원으로 eBPF 사용이 가능해야 함 (CNI Cilium 선택 가능성 있음)
* OS 내부 방화벽기능 제공 ***(firewalld 등)***
* IaC 필수 구성으로, Ansible 등 IaC를 공식 지원하며 사용이 가능해야 함
* 온프렘 구축할 경우, RKE2 고려중이므로 공식 지원 OS 선택해야 함

## 검토된 대안 (Considered Options)

* CoreOS
* SUSE Linux Micro
* Rocky Linux
* Amazon Linux

## 의사결정 결과 (Decision Outcome)

**최종 선택:** 
- **"Rocky Linux"**

**선택 사유:** 
1. 라이선스 비용이 발생되지 않으므로 디자인 패턴 중, 1순위 제약 조건인 TCO 최소화를 완벽히 충족함. 
2. Immutable 구조를 지원하지 않으나, 하이브리드 클러스터 구성 시 온프렘, 클라우드 모두 동일 OS 단일화 작업이 가능하기 때문에, Ansible을 통한 유저 별 파일시스템 R/W 제어로 휴먼 에러를 통제함.
3. 온프레미스, 클라우드 모두 이용하는 하이브리드 아키텍처를 고려중이기 때문에, OS 단일화가 필수적임. 낮은 TCO로 AWS, 온프레미스 모두 높은 호환성을 가지며, cgroup v2, eBPF, firewalld 등을 지원하는 Rocky Linux를 선택하였음.


### 긍정적 효과 (Positive Consequences)
* 라이선스 비용이 없으므로, 워커 노드 증가에 따른 TCO 문제를 해소할 수 있음.
* 온프렘, 클라우드 단일 OS 구조로 Ansible 공통 모듈 작성에 용이함.
* 업스트림 REHL 아키텍처를 지원하기 때문에, Redhat Linux에 익숙한 기존 엔지니어가 동일 RPM 명령어로 패키지 관리가 가능함.(러닝커브를 줄일 수 있음.)
* cgroup v2, eBPF, firewalld, SELinux 모두 지원.
* RKE2 Support Metrix에 공식적으로 지원하는 OS이므로 공식 가이드 그대로 활용 가능함.

### 부작용 및 트레이드오프 (Negative Consequences)
* Immutable 구조 지원하지 않으므로, IaC를 통한 엄격한 파일시스템 별 유저 접근 권한부여가 필요하며 OS 설정 변경 시 작업 절차를 강제해야 함.
* Redhat, SUSE 등의 엔터프라이즈 OS가 아니기 때문에, 기술적 문제 발생 시 엔지니어 역량에 의존해야 함.

## 각 대안별 장단점 (Pros and Cons of the Options)

### RedHat CoreOS

RedHat의 OpenShift 계열 Immutable OS로, 대규모 엔터프라이즈 환경에서 자주 사용됨.

* **장점:** 

    1. Immutable 특성을 가진 OS로, FileSystem R/W를 물리적으로 불가하게끔 제한하였음. 이러한 구조는 잘못된 Config에 의한 휴먼에러를 원천봉쇄할 수 있는 이점이 있음.
    2. OpenShift 통합되어 OS, 컨테이너 까지 관리 영역을 단일화 할 수 있음.
    3. cgroup v2 지원

* **단점:**
    
    1. 엔터프라이즈급 유료 버전 OS기 때문에, WorkerNode Scaling에 따른 TCO가 증가함.
    2. RKE2 지원하지 않음.

### SUSE Linux Micro

SUSE의 Immutable OS로, SAP ERP 솔루션의 OS로 자주 사용됨. 경량 OS.

* **장점:** 
    
    1.  SUSE의 Immutable OS 특성을 가진 OS. FileSystem 전체를 Read 만 가능한 구조로 분리하진 않았음. Btrfs, OverLayFS 구조로 Config가 들어갈 /etc 는 R/W가 가능하며, 타 경로는 ReadOnly 구조임.
    
        BackUp/Restore는 Snapshot을 통해 이루어지기 때문에 정기적인 snapshot update가 필요함.
    2. SUSE Rancher, RKE2 등 SUSE 생태계와 완벽한 호환성 제공
    3. cgroup v2 지원

* **단점:**

    1. 엔터프라이즈급 유료 버전 OS기 때문에, WorkerNode Scaling에 따른 TCO가 증가함.
    2. OverLayFS QoS 관리, Btrfs 스냅샷 등에 대한 추가적인 스토리지 운영 노하우와 모니터링이 필요

### Rocky Linux

CentOS가 EOS되면서 만들어진 OS. REHL 기반으로 만들어졌기 때문에, RPM 패키지와의 안전한 호환성을 제공하는 무료 os임.

* **장점:**

    1. 업스트림 RHEL OS의 다운스트림 버전으로, RHEL 소프트웨어와의 안정적 호환성 제공
    2. 무료 OS이므로 TCO 최소화
    3. SELinux Enforcing 기본 설정으로 보안 최적화
    4. cgroup v2 지원

* **단점:** 

    1. Immutable 구조가 없으므로, 파일시스템 관리 영역이 늘어나며 휴먼 에러 가능성이 높음. 보안 공격 표면또한 넓음.
    2. CentOS와 같이 운영 중 갑작스러운 배포판 지원 종료 문제가 발생할 가능성이 있음.

### Amazon Linux

AWS CLI, SDK, IAM 통합 등 AWS 환경에 최적화된 OS로 추가 비용 없이 AWS에서 사용 가능한 특징이 있음.

* **장점:** 
    
    1. 클라우드에 최적화되어 있어서, 기본적으로 aws cli, sdk가 탑제되어 있음.
    2. cgroup v2 지원
    3. SELinux Enforcing 기본 설정으로 보안 최적화
    4. AWS 이용 시 무료 사용 가능

* **단점:**

    1. AWS 환경(Nitro)에 최적화되어있기 때문에, 동일 OS를 온프레미스에 배포할 경우 커널 패닉이 발생하면서 부팅이 안될 가능성이 아주 높음. 이는 타 클라우드에서도 동일 OS를 사용하지 못한다는 의미가 됨. 따라서 AWS 클라우드 에서만 사용해야 함. **하이브리드 클러스터 구성 시 OS 단일화 불가**
    2. Immutable 구조가 없으므로, Rocky와 동일한 문제 발생.
